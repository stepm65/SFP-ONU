# Eltex NTU-1 rev.C и отключение после O5

Профиль **Eltex NTU-1 rev.C / bridge** находится в разделе «Профили». Это начальный набор настроек для проверки совместимости на базе ODI SFU 240408. Его работа на Eltex OLT ещё не подтверждена. Сам факт достижения O5 не доказывает завершение настройки услуг по OMCI.

## Что делает профиль

Кнопка «Сравнить профиль Eltex с текущими настройками» открывает сравнение с текущими настройками. Запись происходит только после выбора полей и нажатия «Применить выбранное». После применения требуется перезагрузка.

| Параметр | Значение | Назначение |
|---|---|---|
| `OMCI_OLT_MODE` | `0` | Штатный Default Mode |
| `OMCI_FAKE_OK` | `0` | Не подменять ошибки неподдерживаемых OMCI ответом OK |
| `VLAN_CFG_TYPE` | `0` | Получать правила VLAN от OLT |
| `MOD_SWVER` | `0` | Отключить мод подмены версии ПО |
| `MOD_VLAN` | `off` | Отключить локальную правку таблиц VLAN |

Значения режимов Realtek остаются прежними: `0` — стандартный, `1` — Huawei, `2` — ZTE, `3` — пользовательский. Отдельный числовой режим Eltex в закрытый OMCI-демон не добавлен. Название профиля не означает полную эмуляцию NTU-1.

Профиль не меняет GPON SN, PLOAM, LOID, MAC/MACKEY, Vendor ID, Equipment ID, аппаратную версию, OMCC, Traffic Management, `DEVICE_TYPE` и скорость SFP-порта. Их значения нельзя достоверно вывести только из названия терминала. Режим `Default Mode` на штатном NTU-1 служит отправной точкой; он не гарантирует одинаковое поведение двух разных версий OMCI.

## Если O5 держится около минуты

1. Сохраните конфигурацию стика. Версию и разметку flash проверьте по [инструкции установки](03-INSTALL-AND-RECOVERY-RU.md): эта сборка предназначена для базы **V1.1.8-240408 / X100SFP**, k0/k1 `0x14c000`, r0/r1 `0x274000`. Одного названия DFP-34X-2IY2 недостаточно для проверки совместимости.
2. Введите свои параметры регистрации с рабочего терминала; профиль Eltex их не заполняет. Примените профиль, проверьте выбранные изменения и перезагрузите стик.
3. Оставьте страницу «Диагностика PON / OMCI» открытой до обрыва. Нажмите «Прочитать таблицы OMCI» в O5, затем сохраните диагностику после обрыва. История живёт в текущей вкладке; перезагрузка страницы её очищает. Короткие переходы между опросами могут быть пропущены.
4. Сравните uptime и состояние PON. Уменьшение uptime означает перезапуск устройства. Если uptime растёт, а O5 теряется, полная перезагрузка не наблюдалась: нужна диагностика GPON/OMCI и причина отключения на стороне OLT. Это ещё не доказательство конкретной неисправности OMCI.
5. В полном снимке отображается штатный таймер перезагрузки: `0` — выключен, число — минуты от загрузки. «Не удалось прочитать» не означает нулевое значение. Панель только читает `/rebootTime.asp`; изменить таймер можно на штатной странице. Наличие такого таймера само по себе не объясняет обрыв.

Диагностика включает Ethernet UNI (ME 11), bridge port (47), VEIP (329), ONU-G (256), ONU2-G (257), MAC bridge service (45), GEM interworking (266), GEM port (268), T-CONT (262) и таблицы VLAN. Также выгружаются доступные значения `DEVICE_TYPE`, `DUAL_MGMT_MODE`, `OMCI_DBGLVL`, `OMCI_LOGFILE`. Пустая таблица или неподдерживаемый класс сами по себе не означают ошибку: они зависят от созданной OLT модели услуг.

Снимок не атомарный: PON и uptime записываются в начале и в конце сбора. Если исчерпан лимит времени, результат помечается неполным. Это чтение текущего MIB, а не перехват OMCI/PLOAM и не журнал причин деактивации OLT.

Экспорт скрывает строки с серийным номером и паролями, включая `SerialNum` в ONU-G. Перед публичной отправкой всё равно просмотрите файл: неизвестные форматы вывода заводского ПО не могут быть полностью проверены на стендовых данных. Серийные номера и пароли абонентов в репозиторий не включаются.

VLAN 109 и GEM 136 из примера другой линии к Eltex-профилю не относятся. Их нельзя переносить без данных именно этого подключения.
