# Первое подключение и резервная копия

Когда панель уже установлена, резервная копия панели, штатная копия MIB и диагностика доступны через веб-интерфейс без SSH. Дальше — справочная процедура для нового устройства; консольные шаги используются только при наличии доступа.

Сначала сохраняем сведения о приехавшем устройстве. Название в магазине не
доказывает совпадение платы, разметки или заводской прошивки с нашей основой.
До выяснения ревизии оптику оператора можно не подключать.

1. Сфотографируйте наклейку: точная модель, аппаратная ревизия, обозначение
   разъёма. Запишите модель роутера/медиаконвертера и его SFP-порта.
2. Подключите стик к поддерживаемому SFP-порту. Узнайте адрес и реквизиты доступа
   из документации продавца. Часто встречающийся адрес 192.168.1.1 не гарантируется;
   избегайте конфликта с адресом своего роутера. Сначала обеспечьте доступ на 1G,
   если это соответствует настройке стика и возможностям порта.
3. Откройте заводской интерфейс и сохраните конфигурацию через его штатную функцию.
   Запишите заводскую версию, MAC, SN, OUI, PLOAM/LOID, режим порта и VLAN. MAC_KEY
   сохраните вместе с исходным MAC. Эти данные и резервные копии храните приватно.
4. Через доступную консоль выполните только чтение:

```sh
cat /etc/version
cat /proc/mtd
cat /proc/cmdline
cat /proc/mounts
nv getenv sw_active
nv getenv sw_commit
nv getenv sw_version0
nv getenv sw_version1
flash get LAN_SPEED_MODE
flash get LAN_SDS_MODE
```

Ошибка чтения отсутствующего ключа ничего не исправляет и не требует записи.
Нельзя подменять неизвестный результат предположением «наверное банк 0».

5. Сохраните бинарные копии разделов на компьютер. Сначала сопоставьте имена и
   номера по **своему** `/proc/mtd`; не копируйте номера из чужой инструкции.
   Для каждого существующего раздела выполните на компьютере, например:

```sh
ssh admin@АДРЕС 'cat /dev/mtdN' > mtdN.bin
```

Замените АДРЕС и N фактическими значениями. Не используйте SSH с `-t`: нужен
бинарный поток без псевдотерминала. Команда читает раздел; не меняйте направление
перенаправления и не запускайте её на стике как команду записи.
Сохраните boot, env, env2, config, k0/r0, k1/r1 и остальные реальные разделы.
`linux`/`rootfs` могут быть псевдонимами: пометьте их отдельно, не считайте третьим банком.

6. Для каждой копии сравните размер с шестнадцатеричным размером `/proc/mtd` и
   контрольную сумму с чтением на устройстве:

```sh
# На стике
md5sum /dev/mtdN
# На Linux-компьютере
md5sum mtdN.bin
```

MD5 здесь проверяет совпадение передачи, не авторство прошивки. Проверьте код
завершения SSH: пустой или оборванный файл не является резервной копией.

Современный SSH-клиент может отвергать старые алгоритмы сервера. Сначала сохраните
точную ошибку и отпечаток ключа; разрешайте только требуемый алгоритм для конкретного
адреса, не ослабляйте глобальные настройки клиента. При отсутствии SSH используйте
доступный штатный способ выгрузки, не устанавливайте прошивку ради резервного копирования.

Для решения о первой установке нужны фото ревизии, версия, разметка, состояние
банков и подтверждённые копии. Пароли, PLOAM и MAC_KEY для обсуждения присылать не нужно.
