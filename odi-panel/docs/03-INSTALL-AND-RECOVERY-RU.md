# Установка, банки и восстановление

Поддерживается основа ODI SFU V1.1.8-240408.

## Что значит «банк»

| Объект | Назначение |
|---|---|
| k0 + r0 | Ядро и rootfs банка 0 |
| k1 + r1 | Ядро и rootfs банка 1 |
| sw_active | Сведения о работающем банке |
| sw_commit | Выбор следующей загрузки |
| config / env | Общие настройки; переключение банка не создаёт их независимую копию |

Новая установка принимает именно проверенную разметку: k0/k1 по 0x14c000,
r0/r1 по 0x274000, стираемый блок 0x1000. Имена сопоставляются с фактическими MTD,
номера разделов не зашиты. Архив должен иметь шесть обычных файлов, штатные fwu.sh
и точное ядро ODI SFU 240408, hw_ver X100SFP, контрольные суммы и rootfs допустимого размера.
Это ограниченный путь обновления этой основы, не универсальный установщик любых
прошивок Realtek. CRC/структура образа дополнительно проверяются при нашей сборке;
при загрузке CGI сверяет ядро по разрешённой паре размера и хеша и все payload по MD5.
MD5 и метка hw_ver не подтверждают происхождение неизвестного файла: используйте
известные совместимые образы. Не редактируйте метки, чтобы обходить отказ совместимости.

## Первая установка с заводской оболочки

Выбор банка новой панели доступен **после её установки и загрузки**. Добавление
select в чужую заводскую форму не меняет её обработчик.

В предоставленной основе есть `/etc/scripts/fwu_starter.sh BANK FILE`. Если на
приехавшем устройстве подтверждены та же основа, разметка и сам скрипт, можно
использовать его из консоли для первой установки в неактивный банк. До этого
сохраните резервные копии и перенесите TAR в /tmp штатным доступным способом,
сверив SHA256 на компьютере и MD5 переданного файла на стике. ZIP прошивкой не является.

Пример **только для подтверждённого active=0, commit=0**, совместимого образа в
`/tmp/panel.tar` и сохранённого банка 0:

```sh
sh /etc/scripts/fwu_starter.sh 1 /tmp/panel.tar
```

При active=1 целевым будет 0. Не выполняйте пример без проверки этих условий.
Штатный скрипт пишет выбранные k/r и версию, но не даёт всех новых защит панели.
Он выполняет fwu.sh из образа. Пользуйтесь только доверенным TAR; команда не является
рекомендацией запускать неизвестные скрипты. При несовпадении заводской основы
порядок первой установки сначала уточняется по полученным данным.

## Последующие обновления через панель

1. Сохраните копию конфигурации. Закройте другие окна обновления и консольные
   операции записи: блокировка панели не управляет чужими заводскими процессами.
2. В «Прошивке» проверьте текущий банк. Выберите **его же** для следующей загрузки,
   чтобы при неудачной записи следующая перезагрузка сохранила рабочий вариант.
3. В «Установке в выбранный банк» выберите другой банк и TAR. Работающий банк
   недоступен для записи. Подтвердите показанный номер и имя файла.
4. Дождитесь сообщения о проверенной записи. Сначала выполняются проверки архива,
   затем штатная запись и побайтовое сравнение записанных данных с образом.
   Не отключайте питание и не перезагружайте устройство во время операции.
5. После успешной проверки отдельно выберите новый банк для следующей загрузки,
   затем отдельно перезагрузите. До перезагрузки работает прежний банк.

Во время обновления отображаются фактические этапы и прошедшее время. Процент относится только к передаче файла. Запись и проверка памяти показываются названием этапа. Журнал установщика появляется после его завершения.

Чтобы обновить бывший активный банк, сначала загрузитесь из другого известного
рабочего банка. В работающий rootfs установка намеренно запрещена.

## Ошибка или обрыв соединения

Обрыв веб-запроса не доказывает ни успех, ни отказ записи. Сохраните питание,
обновите данные и проверьте состояние операции. На устройстве доступны:

```sh
cat /tmp/odi-panel/firmware-status
cat /tmp/odi-panel/firmware-update.log
nv getenv sw_active
nv getenv sw_commit
```

WRITING — запись начата; VERIFIED — чтение обратно прошло; FAILED — операция
не подтверждена. После потери питания временный статус может отсутствовать.
Файл `/var/config/odi-invalid-bankN` создаётся до записи и удаляется после проверки.
Пока он существует, панель запрещает выбирать N для загрузки. Не удаляйте файл,
чтобы обходить запрет: повторно установите совместимый образ в этот банк.
Загрузчик и заводская оболочка не знают об этой защите; это не автоматический откат
и не гарантия восстановления после отключения питания.

## Откат

Если новая прошивка работает, но не подходит, выберите прежний известный рабочий
банк в панели и перезагрузите. Общая конфигурация не откатывается вместе с rootfs.
При доступной консоли можно прочитать active/commit и установить sw_commit в номер
**заранее проверенного рабочего банка**, затем перезагрузиться. Никогда не угадывайте
номер и не загружайтесь в отмеченный непроверенным банк.

Если нет веба и консоли, сначала исключите потерю IP, VLAN управления и несовместимый
режим SFP. Если нужен UART/загрузчик, распиновку и команды восстановления определяют
по реальной плате и её загрузочному логу. Готовых универсальных команд erase/write
для ещё не полученного устройства здесь нет. Не стирайте boot/env/config по чужой схеме.
