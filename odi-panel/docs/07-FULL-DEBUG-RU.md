# Полная отладка: пароли и полные OMCI-пакеты

В панели есть отдельный режим **Диагностика → Полная отладка с паролями и OMCI**. По умолчанию сеанс не запущен, запись следующей загрузки и передача полной отладки в syslog выключены.

## Что сохраняется

- `raw`, `raw.1`: исходные строки RAW от штатного OMCI-демона. Пакеты не маскируются и не обрезаются; при ротации сохраняются границы строк с полными пакетами.
- `parsed`, `parsed.1`: разобранные штатным SDK сообщения без маскирования паролей.
- `credentials.txt`: доступные значения GPON SN, PLOAM/LOID и паролей, MAC/MAC_KEY, учётных записей устройства и параметров совместимости. Это значения, которые возвращает `flash get`: если сам SDK возвращает шифрованное значение или не поддерживает поле, панель не превращает его в известный открытый пароль.
- `status`, а при наличии также исходная конфигурация штатной трассировки, предыдущие небольшие native-логи, ошибки записи и результат передачи в syslog.

Снимок настроек включает uptime и идентификатор загрузки ядра. Архив называется `ODI-full-debug-PRIVATE.tar`. Обычный экспорт диагностики и обычный журнал событий не включают эти приватные файлы.

## Как записать

Выберите длительность 1, 3, 5 или 10 минут и нажмите **Сохранить и начать запись**. Сеанс работает при закрытом браузере. На странице показаны состояние сеанса и число байт RAW/parsed: нулевые счётчики не подтверждают получение пакетов.

Для захвата первого обмена OMCI отметьте **Запись следующей загрузки → Однократно с запуска OMCI**, сохраните параметры и перезагрузите стик. Параметр потребляется один раз. В сборке изменён штатный `runomci.sh`: при подготовленном сеансе OMCI запускается с `both ffffffff` и записью с первого обмена.

После воспроизведения проблемы нажмите **Остановить запись**, дождитесь состояния остановки и скачайте PRIVATE-архив. По истечении времени запись останавливается автоматически. Новый сеанс заменяет предыдущую приватную запись.

## Ограничение объёма

Данные хранятся в RAM в `/tmp/odi-debug`; перезагрузка их удаляет. Для каждого RAW и parsed файла есть один предшественник, каждый файл до 128 КиБ. Дополнительная пара файлов для полной отправки в syslog также ограничена 128 КиБ на файл. Вместе со снимком настроек, буфером передачи и сохранёнными небольшими native-логами используется около 1 МиБ.

Штатный OMCI-демон пишет в фиксированные `/tmp/omcilog` и `/tmp/omcilog.par`. На время сеанса они становятся FIFO, из которых отдельные читатели сохраняют кольцевые файлы. Полная сеть не блокирует этих читателей: отправитель читает отдельную ограниченную очередь. После остановки сначала выключается штатная трассировка и дочитываются её выходные данные, затем удаляются FIFO. Flash-параметры OMCI_LOGFILE/OMCI_DBGLVL не изменяются; сеанс выключает штатную файловую трассировку по завершении.

Если штатные логи уже существуют, небольшой файл сохраняется в PRIVATE-архиве; файл больше 128 КиБ не удаляется, а подготовка сеанса прекращается. Такой файл можно сначала забрать вручную. Ошибки подготовки или остановки отображаются в статусе. При `stop_failed` читатели продолжают обслуживать FIFO; можно повторить остановку.

RAW этой базы — текстовая последовательность hex-строк, пригодная для дальнейшего преобразования в PCAP. Здесь «полные пакеты» означает сохранность содержимого записанного пакета: ограниченный кольцевой буфер не гарантирует сохранение всей истории длительного сеанса. Аномально длинные записи свыше 16 КиБ отмечаются ошибкой, а не молча обрезаются.

## Полный syslog

Отдельно выберите **RAW-пакеты и пароли на настроенный сервер**. Используются ранее сохранённые IPv4-адрес, TCP-порт и имя стика. При этой явно выбранной настройке на сервер отправляется снимок учётных данных и полные RAW-записи с порядковыми номерами. Разобранный текст остаётся в локальном архиве; RAW содержит исходные пакеты для внешнего декодера.

Сообщения имеют формат RFC 5424 и TCP framing RFC 6587. Транспорт без TLS. Буфер ограничен, доставка не подтверждается приложением, при обрыве сети или переполнении очереди возможна потеря удалённой истории. Локальные RAW/parsed-файлы сохраняются независимо от скорости приёмника.

## Проверки и ограничения

На компьютере проверяются кольцевая запись синтетических кадров без изменения байтов, PRIVATE TAR с немаскированными значениями, отдельная полная отправка на локальный TCP-приёмник, аутентификация/CSRF и запрет произвольных путей и команд. Интерфейс проверяется в jsdom и Chromium.

Запись через штатный `omci_app` в FIFO и захват начальной регистрации требуют проверки на физическом RTL9601D. Для Eltex OLT новая функция пока не испытана; сборка не заявляет исправление самой причины потери O5. Полная отладка создаёт дополнительную нагрузку, поэтому её сеансы ограничены по времени.

Справка: https://hack-gpon.org/omci-wireshark/ . Режимы и фиксированные имена логов дополнительно сверены со скриптом запуска и библиотеками именно SFU 240408.
